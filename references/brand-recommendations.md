# Brand Recommendations: Relationship Bot Kit

Recommendation: position the product as a private relationship operating system, not as a chatbot. “Bot” describes the interface, but the value is memory, preparation, rhythm, and follow-through.

## Naming direction

### Preferred name: AWM Relationship OS Kit

Rationale:

- “Relationship” is the strategic value and keeps the product human.
- “OS” signals an operating rhythm, not another CRM tool.
- “Kit” is honest: this is a setup package that consultants install with Claude Code / Codex.
- It avoids overpromising automation or client-facing message generation.

Best use:

- README title
- internal project name
- setup guide
- future UI header

Suggested one-liner:

> A private relationship operating system for financial consultants, powered by Telegram with your choice of Sheets, CSV, or Obsidian review views.

### Alternative 1: AWM Relationship Desk

Rationale:

- Feels practical, calm, and professional.
- Suggests a daily workspace where the consultant prepares and closes loops.
- Less technical than “OS”.
- Good for non-technical FCs who may not relate to software language.

Tradeoff:

- Slightly less premium and less system-level than “Relationship OS”.

Suggested one-liner:

> A private desk for meeting prep, notes, reminders, recruitment tracking, and daily follow-through.

### Alternative 2: AWM Client Memory Kit

Rationale:

- Extremely clear: the system helps consultants remember what matters.
- Good if the product should feel personal and lightweight.
- Strongly differentiates from content-generation tools.

Tradeoff:

- Too client-specific; it underplays recruitment, coaching, and daily operating rhythm.

Suggested one-liner:

> A lightweight private memory system for client relationships and follow-up discipline.

### Alternative 3: AWM Relationship Ledger

Rationale:

- “Ledger” fits the financial advisory context and implies structured records.
- Premium, serious, and disciplined.
- Good future UI name if the product becomes more data-heavy.

Tradeoff:

- May feel too formal or accounting-oriented for daily Telegram use.

Suggested one-liner:

> A private ledger of relationship context, commitments, and follow-up actions.

## Naming decision

Use **AWM Relationship OS Kit** for now.

It is the best balance between ambition and accuracy. It gives the kit a sharper identity than “Relationship Bot Kit” while still being concrete enough for consultants to understand.

Avoid names that imply:

- outbound automation
- AI-written client messages
- social media generation
- replacement of official systems
- compliance-approved CRM status

## Tone of voice

The documentation should sound like a competent practice manager, not a SaaS landing page.

### Voice principles

1. Direct

Say what the system does in plain terms.

Use:

> Capture rough meeting notes and turn them into structured follow-up records.

Avoid:

> Supercharge your productivity with AI-powered client engagement.

2. Calm

The user may be non-technical. Do not make setup feel fragile.

Use:

> If this step fails, check that the token was pasted without spaces.

Avoid:

> Invalid token. Authentication failed.

3. Boundaried

Be explicit about what the kit does not do.

Use:

> This system does not send messages to clients. It helps you prepare and remember.

Avoid:

> Automate your client communication.

4. Elite but practical

AWM’s broader design direction is premium, dark, angular, and disciplined. The writing should match that: restrained confidence, not hype.

Use:

> Strong relationship work is built on memory, timing, and follow-through.

Avoid:

> Never miss an opportunity again!

### Documentation style rules

- Use short sections.
- Use checklists for setup.
- Use “you” when explaining actions.
- Use “the system” when explaining behaviour.
- Write error recovery in human language.
- Avoid emojis.
- Avoid exclamation marks.
- Avoid marketing clichés: seamless, revolutionary, game-changing, supercharge, unlock.
- Avoid claims that imply compliance approval.

## Color palette for future UI

Use the AWM design language: black, charcoal, cream, and gold. The interface should feel like a private command room, not a consumer chatbot.

### Core palette

- Ink Black: #050505  
  Primary app background. Creates the premium AWM base.

- Charcoal Surface: #0E0E0E  
  Cards, panels, and chat containers.

- Raised Graphite: #1A1A1A  
  Active modules, selected rows, and modal surfaces.

- Border Graphite: #2A2A2A  
  Dividers, card borders, input outlines.

- AWM Gold: #C6A34F  
  Sole accent. Use for priority markers, active states, and key progress.

- Bright Gold: #E2BC6A  
  Hover state or small highlights only. Do not flood the UI with it.

- Warm Paper: #F3EBDD  
  Optional light-mode documentation background or PDF handouts.

- Muted Text: #A6A6A6  
  Secondary body text.

- Primary Text: #F5F1E8  
  Main text on dark surfaces.

### Functional colors

Keep functional colors restrained and secondary to gold.

- Success: #7A8F62  
  Use for “verified” or “connected”. Muted olive, not bright green.

- Warning: #B58B3B  
  Use for recoverable setup warnings.

- Error: #B85C52  
  Use for errors requiring action. Avoid aggressive red unless data loss or security risk is involved.

### UI rules

- One accent only: gold.
- No bright blue SaaS styling.
- No rounded pill buttons.
- Corners: 2–6px.
- Buttons: 4px radius.
- Prefer thin borders over heavy shadows.
- Use spacing and hierarchy instead of decorative icons.

## Typography direction

For AWM-owned web or app surfaces:

- Display: Cormorant Garamond Light
- Body: Barlow
- Condensed labels: Barlow Condensed
- Monospace / setup code: JetBrains Mono

For GitHub-style markdown where custom fonts are unavailable:

- Keep headings clean and sentence-case.
- Use tables sparingly.
- Use code blocks for setup commands and examples.
- Keep line lengths readable.

## Icon and logo concept direction

### Preferred concept: The Relationship Ledger Mark

A minimal angular mark combining:

- a framed square or broken border, matching the AWM lettermark language
- three vertical record lines, suggesting a ledger or database
- one gold node, suggesting the next relationship action

Text description:

```text
+---------+
| | |  ●  |
| | | --- |
| | | --- |
+----  ---+
```

Rationale:

- Feels private and systematic.
- Avoids generic robot imagery.
- Connects to structured memory and follow-up.
- Can scale from README badge to future app icon.

### Alternative concept: The Private Signal

A square Telegram-like message panel inside an AWM angular frame, with one gold line indicating an actionable reminder.

Rationale:

- Makes the Telegram interface obvious.
- Still keeps the brand premium.

Risk:

- Too close to a messaging app identity if overused.

### Concept to avoid: Robot head

Do not use robot faces, chatbot bubbles with eyes, sparkles, or friendly mascot imagery. They make the product feel unserious and imply AI personality rather than disciplined relationship operations.

## Brand positioning statement

Use this internally to keep decisions consistent:

> AWM Relationship OS Kit is a private relationship operations kit for financial consultants. It helps them prepare, capture, remember, and follow through. It does not automate client communication. It makes strong advisory habits easier to run every day.
